01 · ИСТОЧНИК И ОБХОД ЗАЩИТЫ

Обход WAF и соблюдение Rate Limits

Как выкачивать данные без блокировки IP и избегать ошибки HTTP 429.

Проблема и логика

  • Жесткий WAF: Basketball-Reference моментально блокирует стандартный requests или urllib по TLS-отпечатку (JA3/JA4).
  • Имитация Chrome: Библиотека curl_cffi подменяет TLS-handshake на Chrome 110, убирая подозрения бота.
  • Rate Limiting: Лимит ресурса — не более 20 запросов в минуту. Скрипт держит жесткую паузу 3.5 секунды между запросами.
  • Экспоненциальный откат: При редком 429 скрипт уходит в сон на 60 * попытка секунд.

Код: etl/scraper_core.py

from curl_cffi import requests as curl_requests
import time

PAUSE = 3.5
_last_request = 0.0

def safe_get(url: str, retries: int = 3):
    global _last_request
    for attempt in range(retries):
        wait = PAUSE - (time.time() - _last_request)
        if wait > 0:
            time.sleep(wait)
            
        # Подделка отпечатка браузера Chrome
        r = curl_requests.get(url, impersonate="chrome110", timeout=30)
        _last_request = time.time()
        
        if r.status_code == 429:
            delay = 60 * (attempt + 1)
            time.sleep(delay)
            continue
            
        r.raise_for_status()
        return r

Инженерное решение

  • Без платных прокси: Точная эмуляция TLS-стека позволила собирать весь сезон без аренды резидентских прокси.
  • Синхронизация времени: Мониторинг времени последнего запроса защищает от гонки потоков.
02 · ИЗВЛЕЧЕНИЕ ДАННЫХ

Парсинг DOM и координат бросков (Shot Charts)

Раскомментирование скрытого HTML и получение точных координат X/Y каждого броска.

Особенности структуры

  • Скрытые таблицы: Расширенная статистика и карта бросков на странице матча скрыты разработчиками внутри HTML-комментариев <!-- ... -->.
  • Regex Unmasking: Скрипт очищает комментарии перед прогоном через BeautifulSoup, превращая их в стандартные DOM-узлы.
  • Извлечение точек: Координаты бросков вытягиваются из inline-стилей: top: 140px; left: 215px преобразуются в проценты относительно баскетбольного корта.

Код: etl/parse_shots.py

# 1. Извлечение скрытого блока карты бросков
html_clean = re.sub(r"<!--|-->", "", response.text)
soup = BeautifulSoup(html_clean, "html.parser")

shot_divs = soup.select("div.shot-area div.tooltip")
shots_data = []

for div in shot_divs:
    # Парсинг top/left координат корта
    style = div.get("style", "")
    top = int(re.search(r"top:(\d+)px", style).group(1))
    left = int(re.search(r"left:(\d+)px", style).group(1))
    
    shots_data.append({
        "game_id": game_id,
        "player_id": div.get("data-player-id"),
        "x": left,
        "y": top,
        "made": "make" in div.get("class", [])
    })

Результат

  • Полная матрица бросков каждого игрока за матч с признаком попадания/промаха.
  • Готовность для построения тепловых карт результативности в браузере.
03 · ОЧИСТКА И ТРАНСФОРМАЦИЯ

Нормализация имен, времени и связь с NBA API

Устранение диакритических знаков, расчет игрового времени и обогащение метаданными.

Логика трансформации

  • Диакритика (Jokić ➔ Jokic): Для исключения нестыковок в ID имена нормализуются через unicodedata.
  • Формат минут (MP): Строка "34:12" конвертируется в числовой эквивалент (34.2 мин) для расчета темпа и PER.
  • Мерж с nba_api: Basketball-Reference не отдает официальные фото игроков. Скрипт сопоставляет игроков с nba_api и генерирует прямые ссылки на CDN НБА.

Код: etl/transforms.py

import unicodedata

def normalize_player_id(name: str) -> str:
    # Убираем европейские символы (č, ć, š -> c, c, s)
    nfkd = unicodedata.normalize('NFKD', name)
    clean = "".join([c for c in nfkd if not unicodedata.combining(c)])
    return clean.lower().replace(" ", "_")

def parse_minutes(mp_str: str) -> float:
    if not mp_str or ":" not in mp_str:
        return 0.0
    m, s = mp_str.split(":")
    return round(int(m) + int(s) / 60.0, 1)

Проверки качества

  • Автоматический сброс аномалий (минуты > 60).
  • Удаление игроков DNP (Did Not Play) из финального набора данных.
04 · ХРАНЕНИЕ И ЗАГРУЗКА

Идемпотентный UPSERT в PostgreSQL (Supabase)

Пакетная запись чанками без дубликатов при повторных запусках пайплайна.

Архитектура базы данных

  • Реляционные таблицы: Разделение на games (матчи), boxscores (статы) и shots (броски).
  • Идемпотентность: Ключ on_conflict="game_id, player_id" позволяет скрипту безопасно перезапускаться в случае сбоя сети.
  • Batching (Чанки): Запись сотен бросков пакетами по 500 строк снижает нагрузку на соединение.

Код: etl/supabase_loader.py

from supabase import create_client

supabase = create_client(SUPABASE_URL, SUPABASE_KEY)

def load_shots_batch(shots_list, chunk_size=500):
    for i in range(0, len(shots_list), chunk_size):
        chunk = shots_list[i : i + chunk_size]
        # Идемпотентный upsert в Postgres
        supabase.table("nba_shots").upsert(
            chunk, 
            on_conflict="game_id, shot_id"
        ).execute()

# Фиксация статуса в журнале запусков
supabase.table("etl_runs_log").insert({
    "status": "ok",
    "games_processed": len(games)
}).execute()

Схема данных

nba_games game_id (PK), date, home_team, visitor_team
nba_boxscores game_id + player_id (PK), pts, ast, reb, mp
nba_shots shot_id (PK), x, y, made, period
05 · ПРЕДСТАВЛЕНИЕ ДАННЫХ

Оптимизация представлений (SQL Views) и дашборд

Быстрые агрегаты на уровне базы и мгновенная отрисовка в браузере.

Клиентская оптимизация

  • SQL Views: Тяжелые агрегации (средние показатели, TS%, USG%) вынесены в представления БД.
  • Безопасность (RLS): Публичный anon-ключ открывает доступ только к VIEW, закрывая сырые таблицы.
  • Canvas Shot Chart: Отрисовка сотен бросков на элементе <canvas> без нагрузки на DOM-дерево.

SQL: schema/views.sql

CREATE OR REPLACE VIEW v_player_shot_summary AS
SELECT 
    player_id,
    count(*) as total_shots,
    sum(case when made then 1 else 0 end) as made_shots,
    round(avg(case when made then 1.0 else 0.0 end) * 100, 1) as fg_pct
FROM nba_shots
GROUP BY player_id;

-- Публичный доступ только к витрине данных
GRANT SELECT ON v_player_shot_summary TO anon;

Результат

Клиентский интерфейс загружает готовые агрегированные данные менее чем за 150 мс.
